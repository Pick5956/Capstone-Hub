# พิมพ์ใบเสร็จผ่านบลูทูธ (Dishy Mobile)

คู่มือสำหรับทีม — ตั้งแต่ติดตั้งจนพิมพ์ใบเสร็จออกจากเครื่องจริง

> **สถานะ:** ใช้งานได้จริงแล้ว ยืนยันกับ **Xprinter XP-58IIH** — สแกน เลือกเครื่อง และพิมพ์ใบเสร็จภาษาไทยออกมาอ่านได้ครบ
> ยังเหลือข้อจำกัดเรื่องความยาวใบเสร็จ อ่านหัวข้อ [ข้อจำกัดที่ยังไม่ได้แก้](#ข้อจำกัดที่ยังไม่ได้แก้) ก่อนใช้งานจริงหน้าร้าน

---

## ภาพรวม

บิลที่ชำระเงินแล้วสามารถสั่งพิมพ์ออกเครื่องพิมพ์ความร้อน 58 มม. ผ่านบลูทูธได้ (พัฒนาและทดสอบกับ **Xprinter XP-58IIH**)

**ใบเสร็จถูกส่งเป็นภาพ (bitmap) ไม่ใช่ข้อความ ESC/POS** — เพราะเฟิร์มแวร์ของเครื่องรุ่นนี้ไม่มี code page ภาษาไทย ถ้าส่งเป็นข้อความ ภาษาไทยจะออกมาเป็นขยะทุกบรรทัด วิธีนี้ให้มือถือวาดใบเสร็จด้วยฟอนต์ของตัวเองแล้วส่งเป็นภาพ ภาษาไทยจึงออกครบทุกวรรณยุกต์ไม่ว่าเครื่องพิมพ์จะรองรับหรือไม่

### ทำไมใช้ได้แค่ Android

เครื่องพิมพ์กลุ่มนี้สื่อสารด้วย **Bluetooth Classic (SPP)** ส่วน iOS อนุญาตให้ใช้ Bluetooth Classic ได้เฉพาะอุปกรณ์ที่ผ่านการรับรอง **MFi** เท่านั้น ซึ่ง XP-58IIH ไม่มี — แอปของบุคคลที่สามบน iOS จึงเข้าถึงเครื่องพิมพ์นี้ไม่ได้เลย

บน iOS ปุ่มพิมพ์จะถูกซ่อน และหน้า **ตั้งค่า > เครื่องพิมพ์ใบเสร็จ** จะอธิบายเหตุผลให้

**เรื่องนี้แก้ด้วยโค้ดไม่ได้** เป็นข้อจำกัดของฮาร์ดแวร์กับนโยบายของ iOS ถ้าต้องการรองรับ iOS ต้องเปลี่ยนไปใช้เครื่องพิมพ์แบบ BLE หรือแบบต่อผ่านเครือข่าย

## 1. ติดตั้ง Development Build

บลูทูธต้องใช้โค้ด native **Expo Go พิมพ์ไม่ได้** ถ้ากดปุ่มพิมพ์ใน Expo Go จะขึ้นข้อความว่า

> พิมพ์ผ่านบลูทูธใช้ได้ผ่าน Development Build เท่านั้น ไม่รองรับ Expo Go

### ไม่ต้อง build เองทุกคน

ทุกคนในทีมใช้ **APK ตัวเดียวกัน**ได้ แล้วชี้ไป Metro ของเครื่องตัวเอง ดูรายการ build แล้วเปิดลิงก์ APK ล่าสุดบนมือถือ:

```powershell
npx eas-cli login
npx eas-cli build:list --platform android --limit 5
```

ใช้ค่า `Application Archive URL` ของ build ล่าสุดที่สถานะ `finished`

**วิธีส่งลิงก์เข้ามือถือ:** ลิงก์ยาวมาก พิมพ์ตามไม่ไหว ส่งเข้า Line หาตัวเอง / Messenger / อีเมล แล้วกดในมือถือจะง่ายที่สุด

ตอนติดตั้ง Android จะเตือนเรื่อง "ติดตั้งจากแหล่งที่ไม่รู้จัก" ให้กดอนุญาต

### เมื่อไหร่ต้อง build ใหม่

EAS จะลบไฟล์ build ทิ้งหลังผ่านไประยะหนึ่ง ถ้าลิงก์ใช้ไม่ได้แล้ว **หรือมีคนเปลี่ยน native dependency** ให้ build ใหม่:

```powershell
npm run build:android:development
```

⏱️ **build ฟรีมีคิว และคิวนานกว่าเวลา build มาก** — ครั้งแรกของโปรเจกต์นี้รอคิว 58 นาที แล้ว build จริงประมาณ 1 นาที ปิด terminal ได้ไม่ยกเลิก build

✅ **งานที่แก้บ่อยไม่ต้อง build ใหม่** — หน้าตาใบเสร็จใน `mobile/src/components/receipt-slip.tsx`, หน้าเลือกเครื่องพิมพ์, ข้อความ error ทั้งหมดเป็น JavaScript แก้แล้ว Fast Refresh เห็นผลทันที **จะต้อง build ใหม่ก็ต่อเมื่อเพิ่มหรือถอด native module เท่านั้น**

แอปที่ติดตั้งจะชื่อ **Dishy** มีไอคอนของตัวเอง **เป็นคนละแอปกับ Expo Go** — มีแค่ตัวนี้ที่พิมพ์ได้

## 2. จับคู่เครื่องพิมพ์ใน Android ก่อน

เปิดเครื่องพิมพ์ ใส่กระดาษ แล้วไปจับคู่ที่ **ตั้งค่า > บลูทูธ** ของ Android (PIN ปกติคือ `0000` หรือ `1234`)

### ⚠️ อาการที่ดูเหมือนพัง แต่ถูกต้อง

พอกดที่ชื่อเครื่องพิมพ์ **มันจะไม่ขึ้นว่า "กำลังเชื่อมต่อ…" เหมือนตอนต่อหูฟัง** — อย่าเพิ่งคิดว่าพัง

เพราะ Android มี profile เสียง (A2DP) ในตัว ระบบเลยเชื่อมต่อหูฟังให้เองตลอดเวลา แต่ **Android ไม่มี profile สำหรับเครื่องพิมพ์** ระบบจึงแค่ *จับคู่* (bond) ไว้เฉย ๆ แล้วปล่อยให้แอปเป็นคนเปิด socket เองตอนจะพิมพ์ และตัดทันทีที่พิมพ์เสร็จ

**ถ้าชื่อเครื่องไปโผล่ใน "อุปกรณ์ที่จับคู่ไว้" แล้ว = เสร็จเรียบร้อย** ไม่ต้องทำอะไรต่อ

หน้าเลือกเครื่องพิมพ์ในแอปมีการค้นหาอุปกรณ์ใหม่ให้ด้วย แต่การจับคู่ไว้ก่อนคือทางที่เสถียรที่สุดและเป็นทางที่ UI ออกแบบมาให้ใช้เป็นหลัก

## 3. เปิด Backend แล้วรัน Metro

Backend ต้องรันอยู่ก่อน — ที่โฟลเดอร์หลักของโปรเจกต์ ดับเบิลคลิก `start-dishy.bat` (เปิดทั้ง backend และ frontend ให้)

จากนั้นรัน Metro:

```powershell
npm --prefix mobile run start:dev-client:local
```

### ใช้ `start:dev-client:local` อย่าใช้ `start:dev-client`

ตัว `:local` ต่างตรงที่:

- **หา LAN IP ปัจจุบันของเครื่องให้เอง** ป้องกันปัญหา `EXPO_PUBLIC_API_URL` ใน `.env.local` ค้างอยู่ที่ IP เก่า (DHCP เปลี่ยน IP ให้เรื่อย ๆ) ถ้าชี้ผิดแอปจะเปิดมาเป็นหน้าว่างและหาสาเหตุยากมาก
- **เช็คว่า backend ตอบที่พอร์ต 8080 จริงก่อน** ถ้าไม่ตอบจะ error ตั้งแต่ตอนสั่งรัน ดีกว่าไปเจอปัญหาตอนใช้งาน
- โหลด Google OAuth client ID ให้ด้วย

> 💡 ถ้าใช้ PowerShell 5.1 (Windows ปกติ) **`&&` ใช้ไม่ได้** ต้องใช้ `npm --prefix` แบบข้างบน หรือ `cd mobile; if ($?) { npm run ... }`

### เชื่อมมือถือเข้า Metro

ที่หน้าจอ development server ในแอป Dishy ให้ใส่:

```
http://<LAN-IP-ของคอม>:8081
```

หรือกดปุ่ม **Fetch development servers** ให้มันหาเอง

❌ **`http://localhost:8081` ใช้ไม่ได้** เพราะ `localhost` ในมือถือหมายถึงตัวมือถือเอง ไม่ใช่คอม

## 4. เลือกเครื่องพิมพ์ แล้วพิมพ์

1. เข้า **ตั้งค่า > เครื่องพิมพ์ใบเสร็จ > ค้นหาเครื่องพิมพ์**
   อุปกรณ์ที่จับคู่ไว้แล้วจะขึ้นมา**ทันที**และอยู่บนสุด ส่วนการค้นหาอุปกรณ์ใหม่จะทำต่ออีกไม่เกิน 20 วินาที
2. แตะเลือกเครื่องพิมพ์
   แอปจะ**ทดสอบการเชื่อมต่อจริงก่อนบันทึก** ถ้าต่อไม่ได้จะฟ้องตอนนี้เลย ไม่ใช่ไปพังตอนยืนอยู่หน้าลูกค้า
3. เปิดบิลที่ชำระเงินแล้ว กด **พิมพ์ใบเสร็จ**

เครื่องพิมพ์ที่เลือก **ผูกกับตัวมือถือ ไม่ได้ผูกกับบัญชีหรือร้าน** — สลับร้านหรือเปลี่ยนคนล็อกอินแล้วยังจำเครื่องพิมพ์ประจำเคาน์เตอร์นั้นไว้เหมือนเดิม

| **พ่นอักษรจีน/สัญลักษณ์มั่วออกมายาวเป็นเมตร** | ใบเสร็จยาวเกินกว่าที่เครื่องรับไหว สตรีมหลุด | **ปิด-เปิดเครื่องพิมพ์** เพื่อล้างสถานะ แล้วอ่านหัวข้อข้อจำกัดด้านล่าง |

| Google login ฟ้องเรื่อง SHA-1 | SHA-1 ของ keystore ยังไม่ได้ลงทะเบียน | ดูค่าจาก `npx eas-cli credentials` แล้วเพิ่มใน Google Cloud Console — ไม่กระทบการพิมพ์ ล็อกอินด้วยรหัสผ่านได้ปกติ |

## ข้อจำกัดที่ยังไม่ได้แก้

### ⚠️ ใบเสร็จยาวเกินไปแล้วพิมพ์เป็นขยะ

**อาการ:** เครื่องพิมพ์พ่นอักษรจีนกับสัญลักษณ์มั่ว ๆ ออกมายาวหลายเมตร และ**ค้างอยู่ในสถานะนั้นข้ามไปงานพิมพ์ครั้งถัดไปด้วย** ต้องปิด-เปิดเครื่องถึงจะหาย

**สาเหตุ:** ภาพใบเสร็จถูกส่งไปเครื่องพิมพ์ที่ **512 ไบต์ ทุก 35 มิลลิวินาที** (≈14 KB/วินาที ดู `PrintConnection.kt`) พอภาพสูงเกินไป ข้อมูลจะล้นบัฟเฟอร์ของเครื่อง สตรีมหลุด เครื่องอ่าน byte ของภาพต่อไม่ถูกแล้วตีความเป็นตัวอักษรแทน

**ฝั่งแอปไม่รู้ตัวเลย** — `printImage` จะรายงาน `success: true` ตามปกติ เพราะแอปส่งข้อมูลออกไปครบจริง ความผิดพลาดเกิดที่ปลายทาง

**เพดานจริงยังไม่รู้ค่า** ที่ทดสอบมา:

| จำนวนรายการ | ผล |
| --- | --- |
| 11 รายการ (ขนาดฟอนต์ปัจจุบัน) | ✅ ปกติ |
| 11 รายการ + ขยายฟอนต์และระยะบรรทัด ~40% | ❌ พ่นขยะ |
| มากกว่า 11 รายการ | ❓ ยังไม่ได้ทดสอบ |

**ข้อควรระวังสำหรับคนที่จะแก้ `receipt-slip.tsx`:** ทุกอย่างที่ทำให้ใบเสร็จ**สูงขึ้น** — ขนาดฟอนต์ ระยะบรรทัด ช่องไฟ ระยะขอบ — กินโควตานี้หมด ถ้าจะเพิ่มตรงไหนควรไปลดตรงอื่นชดเชย และ**ต้องทดสอบกับบิลที่มีรายการเยอะ ๆ ด้วย** ไม่ใช่แค่บิลสั้น

**ทางแก้ที่ยังไม่ได้ทำ** (เลือกอย่างใดอย่างหนึ่ง):

1. **แบ่งส่งเป็นท่อน** — ตัดภาพเป็นชิ้นสูงไม่เกินประมาณ 600px แล้วส่งทีละชิ้น ให้เครื่องพิมพ์ระบายบัฟเฟอร์ทัน เป็นทางที่แก้ปัญหาจริงและรองรับบิลยาวเท่าไหร่ก็ได้
2. **หาเพดานแล้วกันไว้** — ทดสอบว่าพังที่กี่รายการ แล้วเตือนผู้ใช้หรือแบ่งพิมพ์เป็นหลายใบเมื่อเกิน

### สัญลักษณ์ ฿ ติดกับตัวเลข

ที่ขนาดฟอนต์ปัจจุบัน สัญลักษณ์ **฿** จะเชื่อมกับตัวเลขตัวแรกจนดูเหมือน `$` หรือ `#` ตัวเลขยังอ่านออกครบถ้วน แต่ถ้ารบกวนสายตา แก้ได้โดยเว้นวรรคหลัง ฿ หรือเปลี่ยนเป็น `THB` ใน `receipt.ts`

## ⚠️ กับดัก 2 ข้อ ถ้าจะมาแก้โค้ดต่อ

ทั้งสองข้อนี้ **typecheck จับไม่ได้ และพังแบบเงียบ ๆ** เคยกินเวลาไล่หาสาเหตุไปแล้วทั้งคู่

### 1. Type ของไลบรารีเครื่องพิมพ์ไม่ตรงกับความจริง

`.d.ts` ของ `@finan-me/react-native-thermal-printer` ประกาศว่า:

```ts
scanBluetoothDevices(): Promise<{ paired: BluetoothDevice[]; found: BluetoothDevice[] }>
```

แต่โค้ด Kotlin จริง ๆ ใส่แค่ `success` กับ `error` ลงใน result **ไม่เคยใส่ `paired` หรือ `found` เลย** รายชื่ออุปกรณ์ถูกส่งมาทีหลังผ่าน **event** และเป็น **JSON string**:

```kotlin
params.putString("devices", pairedDevices.toString())
emitRNEvent(EVENT_DEVICE_ALREADY_PAIRED, params)
```

การเขียน `result.paired` จึง typecheck ผ่านสบาย ๆ แต่ได้ `undefined` เสมอ อาการที่เห็นคือ "ค้นหาแล้วไม่พบอุปกรณ์" ทั้งที่จับคู่ไว้แล้ว

`printer-provider.tsx` จึงฟัง `EVENT_DEVICE_ALREADY_PAIRED` / `EVENT_DEVICE_FOUND` / `EVENT_DEVICE_DISCOVER_DONE` แทน และ **ต้องต่อ listener ก่อนเรียก scan** เพราะอุปกรณ์ที่จับคู่ไว้ถูก emit ออกมาระหว่างที่ฟังก์ชัน scan ยังทำงานอยู่

### 2. `AppRefreshControl` ต้อง forward props ที่ได้รับมาให้ครบ

บน Android React Native จะเอา refresh control มาเป็น**ตัวนอกสุด** แล้วยัด `ScrollView` เข้าไปเป็น `children`:

```js
cloneElement(refreshControl, { style }, <ScrollView>...</ScrollView>)
```

wrapper ที่ไม่ส่ง `children` ต่อ = **ลบทั้งหน้าจอทิ้ง** เคยทำให้ 4 จาก 5 แท็บหลักว่างเปล่าบน Android ทั้งที่ iOS ปกติดี

รายละเอียดเต็มอยู่ใน [`android-blank-tabs-postmortem.md`](android-blank-tabs-postmortem.md)
